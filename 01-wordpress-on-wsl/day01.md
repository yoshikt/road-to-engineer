## 1. WSL を最新にして、バージョンを確認する（10分）

### やること

スタートメニューで「ターミナル」を検索して開きます。最初は **PowerShell**（Windows のコマンド画面）が開きます。

まず、WSL を最新にします。次のコマンドを入力して、Enter を押します。

⌨️ **PowerShell で入力**

```powershell
wsl --update
```

終わったら、バージョンを確認します。

⌨️ **PowerShell で入力**

```powershell
wsl --version
```

### 確認ポイント

`WSL バージョン:` が **3.x.x.x** になっていれば OK です。

👀 **表示例**（入力しない）

```text
WSL バージョン: 3.0.1.0
カーネル バージョン: ...
...
```

続けて、インストール済みの Linux（ディストリビューション）を確認します。

⌨️ **PowerShell で入力**

```powershell
wsl -l -v
```

👀 **表示例**（入力しない）

```text
  NAME      STATE           VERSION
* Ubuntu    Stopped         2
```

`Ubuntu` が表示されていれば OK です。

> 💡 ここの `VERSION` 列は、WSL 本体のバージョンとは別物です。数字が 3 になっていなくても問題ありません。

## 2. 「Windows」と「Ubuntu」の違いを知る（10分）

このカリキュラムでは、**2つの OS** を行き来します。初心者がいちばん混乱しやすいところなので、最初に整理しておきましょう。

| | Windows（PowerShell） | Ubuntu（Linux） |
|---|---|---|
| 役割 | 普段使っているパソコン | WordPress を動かすサーバー役 |
| 入力欄の見た目 | `PS C:\Users\taro>` | `taro@PC-NAME:~$` |
| 使うコマンド | `wsl` など Windows のコマンド | `ls` `cd` `apt` など Linux のコマンド |

### やること

ターミナル上部の「∨」から **Ubuntu** を選んで、新しいタブを開きます。

👀 **表示例**（入力しない）

```text
taro@PC-NAME:~$
```

この形になっていれば、Ubuntu の中にいます。それぞれの記号の意味は次のとおりです。

| 部分 | 意味 |
|---|---|
| `taro` | ログイン中のユーザー名 |
| `PC-NAME` | コンピューターの名前（ホスト名） |
| `~` | 今いる場所。`~` は自分のホームディレクトリのこと |
| `$` | 「コマンドを入力してよい」という合図 |

> ⚠️ **教材を読むときのルール**
>
> ⌨️ **PowerShell で入力** と書かれていたら PowerShell のタブで、⌨️ **Ubuntu で入力** と書かれていたら Ubuntu のタブで実行します。間違えるとエラーになります。

<details>
<summary>💡 補足：「PowerShell」と「bash」は何の名前？</summary>

ターミナルの中では、**入力したコマンドを受け取って実行するプログラム** が動いています。このプログラムを **シェル** と呼びます。

| タブ | 動いているシェル |
|---|---|
| PowerShell のタブ | PowerShell（Windows のシェル） |
| Ubuntu のタブ | bash（バッシュ。Linux でよく使われるシェル） |

つまり「PowerShell」は OS の名前ではなくシェルの名前で、Ubuntu の中で同じ役割をしているのが bash です。ほかの教材やネット記事で「bash で実行」と書かれていたら、「Linux のターミナルで実行」と読み替えて構いません。

</details>

### おすすめ設定（任意）

ターミナルの「設定」→「スタートアップ」→「既定のプロファイル」を **Ubuntu** にすると、次からはターミナルを開くだけで Ubuntu に入れます。

## 3. Ubuntu の状態を確認する（15分）

ここからは **Ubuntu のタブ** で作業します。

### 3-1. Ubuntu のバージョン

⌨️ **Ubuntu で入力**

```bash
cat /etc/os-release
```

👀 **表示例**（入力しない）

```text
PRETTY_NAME="Ubuntu 26.04.x LTS"
...
```

`26.04` と表示されれば OK です。

> 💡 `cat` は、ファイルの中身を表示するコマンドです。`/etc/os-release` は、Ubuntu のバージョンなどが書かれたファイルです。`cat` は Day 3 で詳しく学びます。

### 🤔 わざと間違えてみよう

今度は、いま Ubuntu で実行した `cat /etc/os-release` を、**PowerShell のタブ** で実行するとどうなるでしょうか。

> ✋ **実行する前に、予想をメモしてから先へ進みましょう。**

予想を書いたら、PowerShell のタブに切り替えて実行してみます。

⌨️ **PowerShell で入力**

```powershell
cat /etc/os-release
```

<details>
<summary>答え合わせ</summary>

エラーになります（「パスが存在しないため検出できません」といったメッセージが出ます）。

注目してほしいのは、エラーの内容です。「`cat` というコマンドがない」ではなく、「**ファイルが見つからない**」と言われています。

- PowerShell には、Linux のコマンド名で呼べるコマンドが一部用意されています。`cat` を打つと、PowerShell は自分のコマンド（`Get-Content`）に読み替えて実行します。
- ただし、`/etc/os-release` は Ubuntu の中にあるファイルなので、Windows からは見つかりません。

**同じコマンドでも、どちらの OS で打つかによって結果が変わる** ことを覚えておきましょう。読み替えてくれないコマンド（たとえば `apt`）を PowerShell で打つと、「認識されません」というエラーになります。

</details>

確認したら、**Ubuntu のタブ** に戻ります。

### 3-2. systemd が有効か

**systemd** は、Apache や MariaDB などのサーバーソフトを起動・停止する仕組みです。これが無効になっていると、Day 5 以降で使う `systemctl` コマンドが動きません。

⌨️ **Ubuntu で入力**

```bash
ps -p 1 -o comm=
```

| 表示 | 判定 |
|---|---|
| `systemd` | ✅ OK。3-3 へ進む |
| それ以外（`init` など） | ❌ 下の「有効にする手順」を行う |

<details>
<summary>systemd を有効にする手順（❌ だった人だけ）</summary>

1. 設定ファイルを開きます。

   ⌨️ **Ubuntu で入力**

   ```bash
   sudo nano /etc/wsl.conf
   ```

   パスワードを聞かれたら、Ubuntu をインストールしたときに決めたパスワードを入力します。入力中は画面に何も表示されませんが、正常です。

2. 開いた画面に、次の2行を書き足します（すでに `[boot]` の行があれば、その下に `systemd=true` だけ追加します）。

   ⌨️ **nano の画面で書き足す**

   ```ini
   [boot]
   systemd=true
   ```

3. `Ctrl + O` → `Enter` で保存し、`Ctrl + X` で閉じます。

4. **PowerShell のタブ** に切り替えて、WSL を再起動します。

   ⌨️ **PowerShell で入力**

   ```powershell
   wsl --shutdown
   ```

5. Ubuntu のタブを開き直して、もう一度 `ps -p 1 -o comm=` を実行します。`systemd` と表示されれば OK です。

</details>

### 3-3. パッケージを最新にする

ソフトの一覧を最新にして、更新できるものをすべて更新します。意味は Day 5 で学ぶので、今はこのまま実行してください。

⌨️ **Ubuntu で入力**

```bash
sudo apt update && sudo apt upgrade -y
```

数分かかることがあります。最後に `$` が表示されて、入力できる状態に戻れば完了です。

## 4. VS Code と Ubuntu をつなぐ（20分）

Linux の設定ファイルは、基本的にターミナルの中で編集します（Day 3 で練習します）。ただ、ファイルを眺めたり長いファイルを読んだりするときは、慣れたエディタがあると便利です。

### 4-1. VS Code と拡張機能を入れる

1. VS Code が入っていなければ、公式サイトからインストールします（**Windows 側** にインストールします）。
2. VS Code を起動し、左の「拡張機能」アイコンから **「WSL」**（発行元：Microsoft）を検索してインストールします。

### 4-2. Ubuntu から VS Code を開く

Ubuntu のタブで、練習用のフォルダを作ります。

⌨️ **Ubuntu で入力**

```bash
mkdir ~/practice
```

次は、作ったフォルダへ移動するコマンド `cd ~/practice` を実行します。でも、その前に予想です。

> 🤔 **予想しよう**：`cd ~/practice` を実行したあと、プロンプト（`taro@PC-NAME:~$`）はどう変わると思いますか？
>
> ✋ **予想をメモしてから、次のコマンドを実行しましょう。**

⌨️ **Ubuntu で入力**

```bash
cd ~/practice
```

<details>
<summary>答え合わせ</summary>

👀 **表示例**（入力しない）

```text
taro@PC-NAME:~/practice$
```

`~` の部分が `~/practice` に変わりました。プロンプトには **今いる場所** が表示されるので、迷ったらまずプロンプトを見ましょう。

</details>

移動できたら、VS Code を開きます。

⌨️ **Ubuntu で入力**

```bash
code .
```

> 💡 `code .` は「今いるフォルダを VS Code で開く」という意味です。`.` は「今いる場所」を表します。

初回は準備に少し時間がかかります。VS Code の **左下** に `WSL: Ubuntu` と表示されれば、つながっています。

> 💡 **「このフォルダー内のファイルの作成者を信頼しますか?」と聞かれたら**
>
> VS Code は、知らない人が作ったフォルダを開くときに、安全のため一部の機能を止めた「制限モード」で開きます。`practice` は自分で作ったフォルダなので、**「はい、作成者を信頼します」** を選んで構いません。
>
> ネットからダウンロードしたフォルダなど、中身をよく知らないものを開くときは、慎重に判断しましょう。

### 4-3. ファイルを作って、両側から確認する

1. VS Code で `hello.txt` を作り、`Hello, Linux!` と書いて保存します。

2. 🤔 **予想しよう**：VS Code は Windows のアプリです。では、作った `hello.txt` は Ubuntu から見えるでしょうか？

   > ✋ **予想をメモしてから、次へ進みましょう。**

3. Ubuntu のタブに戻って、次のコマンドで確かめます。

   ⌨️ **Ubuntu で入力**

   ```bash
   cat hello.txt
   ```

<details>
<summary>答え合わせ</summary>

`Hello, Linux!` と表示されます。

VS Code は Windows で動いていますが、WSL 拡張機能を通して **Ubuntu の中のファイルを直接編集** しています。左下に `WSL: Ubuntu` と表示されているのがその印です。

</details>

## つまずきやすいポイント

| 症状 | 原因と対処 |
|---|---|
| `wsl: command not found` などと表示される | Ubuntu の中で `wsl` を実行しています。PowerShell のタブで実行しましょう |
| `用語 'apt' は、…認識されません` などと表示される | PowerShell で Linux のコマンドを実行しています。Ubuntu のタブに切り替えましょう |
| `cat` で「パスが存在しないため検出できません」と表示される | PowerShell で実行しています。Ubuntu のタブに切り替えましょう |
| `sudo` のパスワード入力で何も表示されない | 正常です。見えないまま入力して Enter を押します |
| `sudo` のパスワードを忘れた | 講師に相談してください（PowerShell から root で入り、パスワードを設定し直せます） |
| `code .` が動かない | VS Code を一度起動してから、Ubuntu のタブを開き直します |
| VS Code の上部に「制限モード」と表示される | フォルダを信頼していません。自分で作ったフォルダなら、表示をクリックして信頼します |
