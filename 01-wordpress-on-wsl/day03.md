## 1. `vim` でファイルを作る（20分）

サーバーには、VS Code のような画面のあるエディタがないことがほとんどです。そこで、**ターミナルの中で使えるエディタ** を覚えます。

ターミナルで使えるエディタは、いくつもあります。Day 1 で systemd の手順を行った人は、`nano`（ナノ）というエディタを使いました。画面の下に操作が表示される、とっつきやすいエディタです。

このコースでは、今日から `vim`（ヴィム）に統一します。`vim` は、古くからある `vi` というエディタを改良したもので、サーバーの世界で長く使われてきました。`vi` は Linux のサーバーならほぼ必ず入っているので、覚えておけばどのサーバーでも困りません。

> ⚠️ `vim` は、初めて使うと「文字が打てない」「抜け出せない」と戸惑いやすいエディタです。最初は誰でもそうなので、安心してください。今日は **最低限の操作だけ** を覚えます。

<summary>答え（コマンド）</summary>

⌨️ **Ubuntu で入力**

```bash
cd ~/practice
```

</details>

### いちばん大事なこと：2つのモード

`vim` には、**モード** があります。今日使うのは次の2つです。

| モード | できること | 入り方 |
|---|---|---|
| ノーマルモード | 保存する・閉じるなどの **命令** を打つ | `Esc` キー（開いた直後はこのモード） |
| 入力モード | **文字を入力** する | ノーマルモードで `i` キー |

メモ帳や VS Code は、開いたらすぐ文字が打てます。`vim` は違います。**開いた直後は「命令を受け付けるモード」なので、`i` を押すまで文字は入力できません。**

### ファイルを開く

⌨️ **Ubuntu で入力**

```bash
vim greeting.txt
```

> 🔍 **何をしている？**
>
> `vim` のうしろに書いたファイルを、`vim` で開きます。まだないファイルなら、保存したときに作られます。

ターミナルの中に、エディタの画面が開きます。

👀 **表示例**

```text

~
~
~
~
"greeting.txt" [New]
```

左端に並んでいる `~` は「ここにはまだ行がない」という印です。いちばん下の行には、ファイル名などの情報が表示されます。

> 💡 `vim: command not found` と表示されたら、`vim` が入っていません。`sudo apt install -y vim` で入れてから、もう一度開きます。

### 書いて、保存して、閉じる

1. `i` を押します。画面のいちばん下に `-- INSERT --` と表示されたら、入力モードです。
2. 次の2行を入力します。

   ⌨️ **vim の画面で入力**

   ```text
   Hello, vim!
   Today is Day 3.
   ```

3. `Esc` を押します。いちばん下の `-- INSERT --` が消えて、ノーマルモードに戻ります。
4. `:wq` と打って `Enter` を押します。保存して閉じます。

> 🔍 **何をしている？**
>
> ノーマルモードで `:` を打つと、画面のいちばん下に命令を入力できます。`w` は write（保存する）、`q` は quit（閉じる）です。`:wq` で「保存して閉じる」になります。

> 💡 カーソルは **矢印キー** で動かします。
>
> 日本語入力（IME）がオンのままだと、ノーマルモードの命令がうまく打てません。`vim` を使うときは、**半角英数** にしておきましょう。

> ✏️ **自分で打ってみよう**：`greeting.txt` の中身を表示して、保存できたか確かめてください。

<details>
<summary>答え（コマンド）</summary>

⌨️ **Ubuntu で入力**

```bash
cat greeting.txt
```

👀 **表示例**

```text
Hello, vim!
Today is Day 3.
```

</details>

### 保存せずに閉じようとすると

> 🤔 **予想しよう**：`vim` で文字を書き換えたあと、保存せずに `:q`（閉じる）だけを打つと、どうなるでしょうか？
>
> ✋ **予想をメモしてから、試してみましょう。** もう一度 `vim greeting.txt` で開き、`i` で3行目に何か書き足します。`Esc` を押してから `:q` → `Enter` と打ちます。

<details>
<summary>答え合わせ</summary>

閉じられず、画面のいちばん下に次のように表示されます。

👀 **表示例**

```text
E37: No write since last change (add ! to override)
```

「最後の変更が保存されていません（強制するなら ! を付けて）」という意味です。保存していない変更があると、`vim` は勝手に閉じません。

| 打つ命令 | 結果 |
|---|---|
| `:wq` | 保存して閉じる |
| `:q!` | **保存せずに** 閉じる（変更は消える） |

今回は `:wq` で保存しておきましょう。

</details>

### 困ったときの脱出方法

何が起きているか分からなくなったら、次の順に押します。**これだけは必ず覚えてください。**

1. `Esc` を何回か押す（ノーマルモードに戻る）
2. `:q!` と打って `Enter`（保存せずに閉じる）

変な文字が入ってしまっても、保存せずに閉じれば、ファイルは開く前の状態のままです。もう一度開いて、やり直しましょう。

### 覚えておくと便利な操作

ここから下は、すべて **ノーマルモード** で打ちます。

| 操作 | キー |
|---|---|
| 入力モードにする | `i` |
| ノーマルモードに戻る | `Esc` |
| 保存して閉じる | `:wq` → `Enter` |
| 保存せずに閉じる | `:q!` → `Enter` |
| 保存だけする | `:w` → `Enter` |
| ファイルの最後の行へ移動する | `G`（`Shift` + `g`） |
| 今の行の下に新しい行を作って、入力モードにする | `o` |
| カーソルのある行を消す | `dd` |
| 元に戻す | `u` |
| 文字を探す | `/` → 探したい文字 → `Enter`（次を探すときは `n`） |

全部を覚える必要はありません。まずは **`i` → 入力 → `Esc` → `:wq`** の流れと、**脱出方法（`Esc` → `:q!`）** を確実にしましょう。

## 2. 設定ファイルを読む（10分）

### 練習用の設定ファイルを作る

サーバーのソフトは、**設定ファイル** に書かれた内容に従って動きます。まずは練習用の設定ファイルを作ってみましょう。

⌨️ **Ubuntu で入力**

```bash
vim site.conf
```

`i` で入力モードにしてから、次の内容を **手で** 入力します。3行目は空行です。入力したら、`Esc` → `:wq` で保存して閉じます。

⌨️ **vim の画面で入力**

```text
# My site settings
# Lines starting with # are comments

site_name=My First Site
port=80
# debug=true
```

> 🔍 **何をしている？（ファイルの中身）**
>
> - `#` で始まる行は **コメント** です。人間向けのメモで、ソフトは読み飛ばします。
> - `site_name=My First Site` のような「名前=値」の行が、実際の設定です。

### 🤔 この設定、効いている？

> 🤔 **予想しよう**：この `site.conf` を読み込んだソフトにとって、`debug` は有効（true）でしょうか？
>
> ✋ **予想をメモしてから、答えを開きましょう。**

<details>
<summary>答え合わせ</summary>

**有効ではありません。** `# debug=true` は `#` で始まっているので、コメント扱いになり、ソフトは読み飛ばします。

このように、設定の行の先頭に `#` を付けて無効にすることを **コメントアウト** と呼びます。逆に `#` を消して有効にすることもあります。Apache や PHP の設定ファイルでは、「コメントアウトされた設定の例」がたくさん書かれていて、必要なものだけ `#` を消して使います。

</details>

### 長いファイルを読む

本物の設定ファイルは、何百行もあることがあります。`cat` で表示すると、一瞬で流れてしまいます。そんなときは `less` を使います。

Day 2 で見た隠しファイル `.bashrc`（bash の設定ファイル）を読んでみましょう。

⌨️ **Ubuntu で入力**

```bash
less ~/.bashrc
```

> 🔍 **何をしている？**
>
> `less` は、長いファイルを1画面ずつ読むためのコマンドです。読むだけで、書き換えはできません。

| 操作 | キー |
|---|---|
| 次の画面へ | `Space` |
| 前の画面へ | `b` |
| 1行ずつ動く | 矢印キー |
| 文字を探す | `/` → 探したい文字 → `Enter`（次を探すときは `n`） |
| 閉じる | `q` |

`#` で始まるコメントがたくさんあることを確かめたら、`q` で閉じます。

## 3. コピー・移動・削除（10分）

### コピーする

⌨️ **Ubuntu で入力**

```bash
cp greeting.txt greeting-copy.txt
```

> 🔍 **何をしている？**
>
> `cp` は copy の略です。`cp コピー元 コピー先` の順に書きます。

> ✏️ **自分で打ってみよう**：今いるディレクトリの中身を表示して、2つのファイルがあることを確かめてください。

<details>
<summary>答え（コマンド）</summary>

⌨️ **Ubuntu で入力**

```bash
ls
```

👀 **表示例**

```text
greeting-copy.txt  greeting.txt  hello.txt  site.conf
```

</details>

### 名前を変える・移動する

⌨️ **Ubuntu で入力**

```bash
mv greeting-copy.txt memo.txt
```

> 🔍 **何をしている？**
>
> `mv` は move（移動する）の略です。`mv 元の名前 新しい名前` と書くと、**名前を変える** ことになります。Linux では、名前の変更も「別の名前の場所へ移動する」と考えます。

> 🤔 **予想しよう**：`mv` のあと、`greeting-copy.txt` は残っているでしょうか？
>
> ✋ **予想をメモしてから、`ls` で確かめましょう。**

<details>
<summary>答え合わせ</summary>

残っていません。`cp` は元のファイルが残りますが、`mv` は元のファイルが新しい名前に **変わる** ので、元の名前はなくなります。

</details>

次は、ファイルを別のディレクトリに移動します。

> ✏️ **自分で打ってみよう**：今いる場所に、`old` というディレクトリを作ってください。

<details>
<summary>答え（コマンド）</summary>

⌨️ **Ubuntu で入力**

```bash
mkdir old
```

</details>

⌨️ **Ubuntu で入力**

```bash
mv memo.txt old/
```

> 🔍 **何をしている？**
>
> `mv` のうしろにディレクトリを書くと、ファイルをそのディレクトリの中へ移動します。

> ✏️ **自分で打ってみよう**：`old` ディレクトリの中身を表示して、`memo.txt` が移動したことを確かめてください。

<details>
<summary>答え（コマンド）</summary>

⌨️ **Ubuntu で入力**

```bash
ls old
```

</details>

### 削除する

⌨️ **Ubuntu で入力**

```bash
rm old/memo.txt
```

> 🔍 **何をしている？**
>
> `rm` は remove（取り除く）の略で、ファイルを削除します。

> 🤔 **予想しよう**：`rm` で消したファイルは、Windows のように「ごみ箱」から戻せるでしょうか？
>
> ✋ **予想をメモしてから、答えを開きましょう。**

<details>
<summary>答え合わせ</summary>

**戻せません。** `rm` にはごみ箱がなく、確認もなしに、すぐ消えます。

サーバーで大事なファイルを消してしまうと、取り返しがつきません。`rm` を打つときは、Enter を押す前にもう一度ファイル名を見直す習慣を付けましょう。

</details>

空になった `old` ディレクトリも消してみましょう。

> 🤔 **予想しよう**：`rm old` で、ディレクトリを消せるでしょうか？
>
> ✋ **予想をメモしてから、実行してみましょう。**

<details>
<summary>答え合わせ</summary>

👀 **表示例**

```text
rm: cannot remove 'old': Is a directory
```

「それはディレクトリです」と言われて、消せません。ディレクトリを消すには、`-r` オプションを付けます。

⌨️ **Ubuntu で入力**

```bash
rm -r old
```

> 🔍 **何をしている？**
>
> `-r` は recursive（中身ごとすべて）の意味で、ディレクトリを **中のファイルごと** 削除します。

> ⚠️ ネットで `rm -rf` というコマンドを見かけることがあります。確認なしに、中身ごと強制的に消すコマンドです。場所を間違えると、システムを壊すこともあります。意味が分からないうちは使わないでください。

</details>

## 4. 設定ファイルを安全に書き換える（10分）

サーバーの設定ファイルを書き換えるときは、次の **作法** を守ります。

1. 書き換える前に、**バックアップ** を取る
2. 書き換える
3. **どこを変えたか** を確かめる
4. うまくいかなければ、バックアップから **元に戻す**

`site.conf` で練習してみましょう。

### 1. バックアップを取る

> ✏️ **自分で打ってみよう**：`site.conf` を `site.conf.bak` という名前でコピーしてください。

<details>
<summary>答え（コマンド）</summary>

⌨️ **Ubuntu で入力**

```bash
cp site.conf site.conf.bak
```

> 💡 `.bak` は backup の略です。バックアップのファイル名には、元の名前のうしろに `.bak` を付けることがよくあります。

</details>

### 2. 書き換える

> ✏️ **自分で打ってみよう**：`site.conf` を `vim` で開いてください。

<details>
<summary>答え（コマンド）</summary>

⌨️ **Ubuntu で入力**

```bash
vim site.conf
```

</details>

次の2か所を書き換えて、保存して閉じます。矢印キーで書き換えたい行に移動し、`i` で入力モードにして書き換えます。終わったら `Esc` → `:wq` です。

- `port=80` を `port=8080` にする
- `# debug=true` の `# ` を消して、`debug=true` にする

### 3. どこを変えたか確かめる

⌨️ **Ubuntu で入力**

```bash
diff site.conf.bak site.conf
```

> 🔍 **何をしている？**
>
> `diff` は difference（違い）の略で、2つのファイルを比べて、違う行だけを表示します。

👀 **表示例**

```text
5,6c5,6
< port=80
< # debug=true
---
> port=8080
> debug=true
```

`<` の行が元のファイル（`site.conf.bak`）、`>` の行が書き換えたあとのファイル（`site.conf`）です。**意図した2か所だけが変わっている** ことが確かめられます。

### 4. 元に戻す

うまくいかなかったことにして、バックアップから元に戻してみましょう。

⌨️ **Ubuntu で入力**

```bash
cp site.conf.bak site.conf
```

> ✏️ **自分で打ってみよう**：`site.conf` の中身を表示して、`port=80` に戻ったことを確かめてください。

<details>
<summary>答え（コマンド）</summary>

⌨️ **Ubuntu で入力**

```bash
cat site.conf
```

</details>

> ⚠️ `cp` と `mv` は、コピー先や移動先に同じ名前のファイルがあると、**確認なしに上書き** します。今回はそれを利用して元に戻しましたが、うっかり大事なファイルを上書きしないよう気を付けましょう。

> 💡 本物の設定ファイルの多くは `/etc` の中にあり、書き換えるには管理者の権限（`sudo`）が必要です。権限の仕組みは Day 4 で学びます。

## 5. 既定のエディタを vim にする（5分）

Ubuntu では、ほかのコマンドから呼び出されるエディタが、最初は `nano` になっています。たとえば、この先で使う「定期的にコマンドを実行する設定」（`crontab -e`）や、Git の記録（`git commit`）では、自動でエディタが開きます。

今日から vim に統一するので、ここでも vim が開くように設定を変えましょう。せっかくなので、4章の **作法** どおりに、本物の設定ファイルを書き換えます。

書き換えるのは、2章で読んだ bash の設定ファイル `~/.bashrc` です。

### 1. バックアップを取る

> ✏️ **自分で打ってみよう**：`~/.bashrc` を `~/.bashrc.bak` という名前でコピーしてください。

<details>
<summary>答え（コマンド）</summary>

⌨️ **Ubuntu で入力**

```bash
cp ~/.bashrc ~/.bashrc.bak
```

</details>

### 2. 書き換える

> ✏️ **自分で打ってみよう**：`~/.bashrc` を `vim` で開いてください。

<details>
<summary>答え（コマンド）</summary>

⌨️ **Ubuntu で入力**

```bash
vim ~/.bashrc
```

</details>

ファイルの **いちばん最後** に、次の3行を書き足します。

1. `G`（`Shift` + `g`）を押して、最後の行へ移動します。
2. `o` を押します。最後の行の下に新しい行ができて、入力モードになります。
3. 次の3行を入力します。

   ⌨️ **vim の画面で入力**

   ```text
   # Use vim as the default editor
   export EDITOR=vim
   export VISUAL=vim
   ```

4. `Esc` → `:wq` で保存して閉じます。

> 🔍 **何をしている？（書き足した内容）**
>
> `EDITOR` と `VISUAL` は、「エディタを開くときは、これを使ってね」とほかのソフトに伝えるための設定です。`export EDITOR=vim` で、その値を `vim` にしています。1行目は `#` で始まるので、自分向けのメモ（コメント）です。

### 3. どこを変えたか確かめる

> ✏️ **自分で打ってみよう**：バックアップと書き換えたあとのファイルを比べて、違いを表示してください。

<details>
<summary>答え（コマンド）</summary>

⌨️ **Ubuntu で入力**

```bash
diff ~/.bashrc.bak ~/.bashrc
```

👀 **表示例**（いちばん上の数字は、環境によって違います）

```text
117a118,120
> # Use vim as the default editor
> export EDITOR=vim
> export VISUAL=vim
```

`>` の3行だけが増えていれば OK です。

</details>

### 4. 設定を読み込み直す

`~/.bashrc` は、ターミナルを開いたときに読み込まれます。今開いているターミナルに反映させるには、次のコマンドを実行します。

⌨️ **Ubuntu で入力**

```bash
source ~/.bashrc
```

> 🔍 **何をしている？**
>
> `source` は、ファイルに書かれた設定を、今のターミナルに読み込むコマンドです。ターミナルのタブを開き直しても、同じ結果になります。

設定が効いているか確かめます。

⌨️ **Ubuntu で入力**

```bash
echo $EDITOR
```

> 🔍 **何をしている？**
>
> `echo` は、うしろに書いたものを表示するコマンドです。`$EDITOR` と `$` を付けると、`EDITOR` という名前の設定の **値** を表示します。

👀 **表示例**

```text
vim
```

`vim` と表示されれば OK です。これで、ほかのコマンドからエディタが開くときも vim になります。

> 💡 `source ~/.bashrc` でエラーが出たら、書き足した行に打ち間違いがあります。`vim ~/.bashrc` で開き直して直すか、`cp ~/.bashrc.bak ~/.bashrc` でバックアップから元に戻して、やり直しましょう。

### 確認問題

1. `vim` で文字を入力したあと、保存して閉じるには、どのキーを押しますか？
2. 設定ファイルの `# Listen 8080` という行は、設定として効いていますか？
3. `cp` と `mv` の違いは何ですか？
4. 設定ファイルを書き換える前に、バックアップを取るのはなぜですか？

<details>
<summary>解答</summary>

1. `Esc` でノーマルモードに戻り、`:wq` → `Enter`
2. 効いていない。`#` で始まる行はコメントなので、ソフトは読み飛ばす
3. `cp` は元のファイルが残る。`mv` は元のファイルが新しい場所・名前に変わり、元の名前は残らない
4. 書き換えてうまく動かなくなったときに、元の状態に戻せるようにするため。また、`diff` で変更した場所を確かめられる

</details>

## つまずきやすいポイント

| 症状 | 原因と対処 |
|---|---|
| `vim` から抜け出せない | `Esc` を何回か押してから、`:q!` → `Enter` で閉じます（保存はされません） |
| `vim` で文字を打っても入力されない、または変な動きをする | ノーマルモードのままです。`i` を押して、下に `-- INSERT --` が出てから入力します |
| `:wq` と打っても、その文字が本文に入ってしまう | 入力モードのままです。先に `Esc` を押します |
| `:wq` などの命令が効かない | 日本語入力がオンになっています。半角英数に切り替えます |
| `E37: No write since last change` | 保存していない変更があります。保存するなら `:wq`、捨てるなら `:q!` |
| `less` から抜け出せない | `q` を押します |
| `rm: cannot remove '…': Is a directory` | ディレクトリを消すには `rm -r` を使います |
| ファイルを消してしまった | `rm` で消したファイルは戻せません。大事なファイルは、先にバックアップを取りましょう |
| 保存したはずなのに中身が変わっていない | `:q!` で閉じた可能性があります。もう一度開いて確かめましょう |
| `echo $EDITOR` で何も表示されない | `source ~/.bashrc` を忘れているか、書き足した行に打ち間違いがあります。`diff ~/.bashrc.bak ~/.bashrc` で確かめましょう |
| `source ~/.bashrc` でエラーが出る | 書き足した行に打ち間違いがあります。直すか、`cp ~/.bashrc.bak ~/.bashrc` で元に戻しましょう |
