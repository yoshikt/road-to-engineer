## 1. `nano` でファイルを作る（20分）

サーバーには、VS Code のような画面のあるエディタがないことがほとんどです。そこで、**ターミナルの中で使えるエディタ** を覚えます。このコースでは、操作が分かりやすい `nano`（ナノ）を使います。

> ✏️ **自分で打ってみよう**：Day 1 で作った `practice` ディレクトリに移動してください。

<details>
<summary>答え（コマンド）</summary>

⌨️ **Ubuntu で入力**

```bash
cd ~/practice
```

</details>

### ファイルを開く

⌨️ **Ubuntu で入力**

```bash
nano greeting.txt
```

> 🔍 **何をしている？**
>
> `nano` のうしろに書いたファイルを、`nano` で開きます。まだないファイルなら、保存したときに作られます。

ターミナルの中に、エディタの画面が開きます。

👀 **表示例**（下の段の内容は、バージョンによって少し違います）

```text
  GNU nano 8.x                greeting.txt
（ここに文字を入力する）




^G Help      ^O Write Out  ^W Where Is   ^K Cut        ...
^X Exit      ^R Read File  ^\ Replace    ^U Paste      ...
```

画面の下にあるのが、操作の一覧です。**`^` は `Ctrl` キー** を表します。たとえば `^X` は `Ctrl` + `X` です。

### 書いて、保存して、閉じる

1. 次の2行を入力します。

   ⌨️ **nano の画面で入力**

   ```text
   Hello, nano!
   Today is Day 3.
   ```

2. `Ctrl` + `O` を押します。画面の下に `File Name to Write: greeting.txt` と表示されるので、そのまま `Enter` を押します。これで保存されます。
3. `Ctrl` + `X` を押して、`nano` を閉じます。

> 💡 `nano` の中では、マウスで文字の位置を動かせません。**矢印キー** でカーソルを動かします。

> ✏️ **自分で打ってみよう**：`greeting.txt` の中身を表示して、保存できたか確かめてください。

<details>
<summary>答え（コマンド）</summary>

⌨️ **Ubuntu で入力**

```bash
cat greeting.txt
```

👀 **表示例**

```text
Hello, nano!
Today is Day 3.
```

</details>

### 保存せずに閉じようとすると

> 🤔 **予想しよう**：`nano` で文字を書き換えたあと、保存（`Ctrl` + `O`）をせずに `Ctrl` + `X` を押すと、どうなるでしょうか？
>
> ✋ **予想をメモしてから、試してみましょう。** もう一度 `nano greeting.txt` で開き、3行目に何か書き足してから `Ctrl` + `X` を押します。

<details>
<summary>答え合わせ</summary>

画面の下に、次のように聞かれます。

👀 **表示例**

```text
Save modified buffer?
 Y Yes
 N No           ^C Cancel
```

「変更を保存しますか？」という意味です。

| 押すキー | 結果 |
|---|---|
| `Y` | 保存する（続けてファイル名を聞かれるので `Enter`） |
| `N` | 保存せずに閉じる（変更は消える） |
| `Ctrl` + `C` | 閉じるのをやめて、編集に戻る |

いきなり変更が消えることはないので、安心して `Ctrl` + `X` を押して構いません。今回は `Y` → `Enter` で保存しておきましょう。

</details>

### 覚えておくと便利な操作

| 操作 | キー |
|---|---|
| 保存 | `Ctrl` + `O` → `Enter` |
| 閉じる | `Ctrl` + `X` |
| 1行切り取る | `Ctrl` + `K` |
| 貼り付ける | `Ctrl` + `U` |
| 文字を探す | `Ctrl` + `W` → 探したい文字 → `Enter` |
| 元に戻す | `Alt` + `U` |

全部を覚える必要はありません。まずは **保存と閉じる** の2つを確実にしましょう。

## 2. 設定ファイルを読む（10分）

### 練習用の設定ファイルを作る

サーバーのソフトは、**設定ファイル** に書かれた内容に従って動きます。まずは練習用の設定ファイルを作ってみましょう。

⌨️ **Ubuntu で入力**

```bash
nano site.conf
```

次の内容を **手で** 入力して、保存して閉じます。3行目は空行です。

⌨️ **nano の画面で入力**

```text
# My site settings
# Lines starting with # are comments

site_name=My First Site
port=80
# debug=true
```

> 🔍 **何をしている？（ファイルの中身）**
>
> - `#` で始まる行は **コメント** です。人間向けのメモで、ソフトは読み飛ばします。
> - `site_name=My First Site` のような「名前=値」の行が、実際の設定です。

### 🤔 この設定、効いている？

> 🤔 **予想しよう**：この `site.conf` を読み込んだソフトにとって、`debug` は有効（true）でしょうか？
>
> ✋ **予想をメモしてから、答えを開きましょう。**

<details>
<summary>答え合わせ</summary>

**有効ではありません。** `# debug=true` は `#` で始まっているので、コメント扱いになり、ソフトは読み飛ばします。

このように、設定の行の先頭に `#` を付けて無効にすることを **コメントアウト** と呼びます。逆に `#` を消して有効にすることもあります。Apache や PHP の設定ファイルでは、「コメントアウトされた設定の例」がたくさん書かれていて、必要なものだけ `#` を消して使います。

</details>

### 長いファイルを読む

本物の設定ファイルは、何百行もあることがあります。`cat` で表示すると、一瞬で流れてしまいます。そんなときは `less` を使います。

Day 2 で見た隠しファイル `.bashrc`（bash の設定ファイル）を読んでみましょう。

⌨️ **Ubuntu で入力**

```bash
less ~/.bashrc
```

> 🔍 **何をしている？**
>
> `less` は、長いファイルを1画面ずつ読むためのコマンドです。読むだけで、書き換えはできません。

| 操作 | キー |
|---|---|
| 次の画面へ | `Space` |
| 前の画面へ | `b` |
| 1行ずつ動く | 矢印キー |
| 文字を探す | `/` → 探したい文字 → `Enter`（次を探すときは `n`） |
| 閉じる | `q` |

`#` で始まるコメントがたくさんあることを確かめたら、`q` で閉じます。

## 3. コピー・移動・削除（15分）

### コピーする

⌨️ **Ubuntu で入力**

```bash
cp greeting.txt greeting-copy.txt
```

> 🔍 **何をしている？**
>
> `cp` は copy の略です。`cp コピー元 コピー先` の順に書きます。

> ✏️ **自分で打ってみよう**：今いるディレクトリの中身を表示して、2つのファイルがあることを確かめてください。

<details>
<summary>答え（コマンド）</summary>

⌨️ **Ubuntu で入力**

```bash
ls
```

👀 **表示例**

```text
greeting-copy.txt  greeting.txt  hello.txt  site.conf
```

</details>

### 名前を変える・移動する

⌨️ **Ubuntu で入力**

```bash
mv greeting-copy.txt memo.txt
```

> 🔍 **何をしている？**
>
> `mv` は move（移動する）の略です。`mv 元の名前 新しい名前` と書くと、**名前を変える** ことになります。Linux では、名前の変更も「別の名前の場所へ移動する」と考えます。

> 🤔 **予想しよう**：`mv` のあと、`greeting-copy.txt` は残っているでしょうか？
>
> ✋ **予想をメモしてから、`ls` で確かめましょう。**

<details>
<summary>答え合わせ</summary>

残っていません。`cp` は元のファイルが残りますが、`mv` は元のファイルが新しい名前に **変わる** ので、元の名前はなくなります。

</details>

次は、ファイルを別のディレクトリに移動します。

> ✏️ **自分で打ってみよう**：今いる場所に、`old` というディレクトリを作ってください。

<details>
<summary>答え（コマンド）</summary>

⌨️ **Ubuntu で入力**

```bash
mkdir old
```

</details>

⌨️ **Ubuntu で入力**

```bash
mv memo.txt old/
```

> 🔍 **何をしている？**
>
> `mv` のうしろにディレクトリを書くと、ファイルをそのディレクトリの中へ移動します。

> ✏️ **自分で打ってみよう**：`old` ディレクトリの中身を表示して、`memo.txt` が移動したことを確かめてください。

<details>
<summary>答え（コマンド）</summary>

⌨️ **Ubuntu で入力**

```bash
ls old
```

</details>

### 削除する

⌨️ **Ubuntu で入力**

```bash
rm old/memo.txt
```

> 🔍 **何をしている？**
>
> `rm` は remove（取り除く）の略で、ファイルを削除します。

> 🤔 **予想しよう**：`rm` で消したファイルは、Windows のように「ごみ箱」から戻せるでしょうか？
>
> ✋ **予想をメモしてから、答えを開きましょう。**

<details>
<summary>答え合わせ</summary>

**戻せません。** `rm` にはごみ箱がなく、確認もなしに、すぐ消えます。

サーバーで大事なファイルを消してしまうと、取り返しがつきません。`rm` を打つときは、Enter を押す前にもう一度ファイル名を見直す習慣を付けましょう。

</details>

空になった `old` ディレクトリも消してみましょう。

> 🤔 **予想しよう**：`rm old` で、ディレクトリを消せるでしょうか？
>
> ✋ **予想をメモしてから、実行してみましょう。**

<details>
<summary>答え合わせ</summary>

👀 **表示例**

```text
rm: cannot remove 'old': Is a directory
```

「それはディレクトリです」と言われて、消せません。ディレクトリを消すには、`-r` オプションを付けます。

⌨️ **Ubuntu で入力**

```bash
rm -r old
```

> 🔍 **何をしている？**
>
> `-r` は recursive（中身ごとすべて）の意味で、ディレクトリを **中のファイルごと** 削除します。

> ⚠️ ネットで `rm -rf` というコマンドを見かけることがあります。確認なしに、中身ごと強制的に消すコマンドです。場所を間違えると、システムを壊すこともあります。意味が分からないうちは使わないでください。

</details>

## 4. 設定ファイルを安全に書き換える（10分）

サーバーの設定ファイルを書き換えるときは、次の **作法** を守ります。

1. 書き換える前に、**バックアップ** を取る
2. 書き換える
3. **どこを変えたか** を確かめる
4. うまくいかなければ、バックアップから **元に戻す**

`site.conf` で練習してみましょう。

### 1. バックアップを取る

> ✏️ **自分で打ってみよう**：`site.conf` を `site.conf.bak` という名前でコピーしてください。

<details>
<summary>答え（コマンド）</summary>

⌨️ **Ubuntu で入力**

```bash
cp site.conf site.conf.bak
```

> 💡 `.bak` は backup の略です。バックアップのファイル名には、元の名前のうしろに `.bak` を付けることがよくあります。

</details>

### 2. 書き換える

> ✏️ **自分で打ってみよう**：`site.conf` を `nano` で開いてください。

<details>
<summary>答え（コマンド）</summary>

⌨️ **Ubuntu で入力**

```bash
nano site.conf
```

</details>

次の2か所を書き換えて、保存して閉じます。

- `port=80` を `port=8080` にする
- `# debug=true` の `# ` を消して、`debug=true` にする

### 3. どこを変えたか確かめる

⌨️ **Ubuntu で入力**

```bash
diff site.conf.bak site.conf
```

> 🔍 **何をしている？**
>
> `diff` は difference（違い）の略で、2つのファイルを比べて、違う行だけを表示します。

👀 **表示例**

```text
5,6c5,6
< port=80
< # debug=true
---
> port=8080
> debug=true
```

`<` の行が元のファイル（`site.conf.bak`）、`>` の行が書き換えたあとのファイル（`site.conf`）です。**意図した2か所だけが変わっている** ことが確かめられます。

### 4. 元に戻す

うまくいかなかったことにして、バックアップから元に戻してみましょう。

⌨️ **Ubuntu で入力**

```bash
cp site.conf.bak site.conf
```

> ✏️ **自分で打ってみよう**：`site.conf` の中身を表示して、`port=80` に戻ったことを確かめてください。

<details>
<summary>答え（コマンド）</summary>

⌨️ **Ubuntu で入力**

```bash
cat site.conf
```

</details>

> ⚠️ `cp` と `mv` は、コピー先や移動先に同じ名前のファイルがあると、**確認なしに上書き** します。今回はそれを利用して元に戻しましたが、うっかり大事なファイルを上書きしないよう気を付けましょう。

> 💡 本物の設定ファイルの多くは `/etc` の中にあり、書き換えるには管理者の権限（`sudo`）が必要です。権限の仕組みは Day 4 で学びます。

## 5. 振り返り（5分）

### チェックリスト

> 💡 GitHub 上ではチェックボックスをクリックできません。自分のメモに書き写して、できたものに印を付けていきましょう。

- [ ] `nano` でファイルを開き、書き換えて、保存して閉じられる
- [ ] コメント（`#`）とコメントアウトの意味を説明できる
- [ ] `less` で長いファイルを読み、`q` で閉じられる
- [ ] `cp` `mv` `rm` でファイルをコピー・移動・削除できる
- [ ] バックアップ → 編集 → `diff` で確認 → 元に戻す、の流れを一度やった
- [ ] `~/notes/memo.md` に今日のメモを書いた

### 今日使ったコマンド

| コマンド | 何をする |
|---|---|
| `nano ファイル` | ファイルを `nano` で開く（なければ保存時に作る） |
| `less ファイル` | 長いファイルを1画面ずつ読む |
| `cp コピー元 コピー先` | ファイルをコピーする |
| `mv 元 先` | ファイルを移動する・名前を変える |
| `rm ファイル` | ファイルを削除する（戻せない） |
| `rm -r ディレクトリ` | ディレクトリを中身ごと削除する |
| `diff ファイル1 ファイル2` | 2つのファイルの違いを表示する |

### 確認問題

1. `nano` で書き換えたあと、保存して閉じるには、どのキーを押しますか？
2. 設定ファイルの `# Listen 8080` という行は、設定として効いていますか？
3. `cp` と `mv` の違いは何ですか？
4. 設定ファイルを書き換える前に、バックアップを取るのはなぜですか？

<details>
<summary>解答</summary>

1. `Ctrl` + `O` → `Enter` で保存し、`Ctrl` + `X` で閉じる（`Ctrl` + `X` → `Y` → `Enter` でも可）
2. 効いていない。`#` で始まる行はコメントなので、ソフトは読み飛ばす
3. `cp` は元のファイルが残る。`mv` は元のファイルが新しい場所・名前に変わり、元の名前は残らない
4. 書き換えてうまく動かなくなったときに、元の状態に戻せるようにするため。また、`diff` で変更した場所を確かめられる

</details>

## つまずきやすいポイント

| 症状 | 原因と対処 |
|---|---|
| `nano` から抜け出せない | `Ctrl` + `X` で閉じます。保存するか聞かれたら `Y` か `N` を押します |
| `nano` でマウスでクリックしても、カーソルが動かない | `nano` では矢印キーでカーソルを動かします |
| `less` から抜け出せない | `q` を押します |
| `rm: cannot remove '…': Is a directory` | ディレクトリを消すには `rm -r` を使います |
| ファイルを消してしまった | `rm` で消したファイルは戻せません。大事なファイルは、先にバックアップを取りましょう |
| 保存したはずなのに中身が変わっていない | 保存のときに `Enter` を押し忘れたか、`N` を押して閉じた可能性があります。もう一度開いて確かめましょう |
